# AGENTS.md — Villain Arc

Standing instructions for any agent working in this repo. Pointers only: read the file named, don't assume its contents.

- **Read first: [`VillainArc/Documentation/PROJECT_GUIDE.md`](VillainArc/Documentation/PROJECT_GUIDE.md)**, then the flow doc for the area (`SYNC_FLOW`, `SESSION_LIFECYCLE_FLOW`, `HEALTHKIT_INTEGRATION`, `ONBOARDING_FLOW`, …). Intent coverage: `APP_INTENTS_AUDIT.md`, same folder.
- **The gate is `scripts/gate.sh`, and nothing is done until it is green.** It builds Debug and Release, archives, runs the suite, and reads the built artifacts (App Shortcut registration + phrase coverage, app icon, a privacy manifest per bundle, localization drift and locale completeness). Point `SIM_NAME` at your own simulator when another lane is running. `scripts/loc-check.sh` runs the locale half alone; `scripts/a11y-coverage.py VillainArc --list-gaps` measures the identifier bar: every interactive control carries a stable id from `AccessibilityIdentifiers`, and new UI keeps it that way. `scripts/install-ios.sh` builds Release and installs on the paired iPhone (signing and provisioning are automatic; it verifies shortcut registration on the built artifact and retains the dSYM a later crash report will name).
- **Ten shipping locales** (en, de, es, fr, it, ja, ko, pt-BR, ru, zh-Hans), complete in every catalog: `VillainArc/Localizable.xcstrings`, `VillainArc/AppShortcuts.xcstrings` (the Siri phrases — a phrase key in `Localizable` serves nothing), `VillainArcWatchApp/Localizable.xcstrings`. Strings declared in FCTFoundation resolve against the app's bundle, so they belong in the app's catalog too. Adding UI copy means adding its ten translations; `LocalizationIntegrityTests` fails the gate otherwise.
- **The platform citizen shape:** iOS 27 minimum, built on FCTFoundation (`../FCTFoundation`, local path dependency — a sibling checkout is required to build). The store is local-first SwiftData in the App Group with NO CloudKit anywhere; what the app authors syncs through the FCT platform under the mandatory FCT account (`SYNC_FLOW.md`). All code lives in the app target — no per-app Kit package.
- **The schema is the clean, unpublished `VillainArcSchemaV1`:** live models are the schema, shape changes are made in place, and a dev device takes a full store reset (delete the app AND the App-Group `VillainArc.store*` files — the store survives an app delete on its own). Every `@Model` goes in the schema array (pinned by `SchemaContractTests`); a synced model's `id` carries `@Attribute(.preserveValueOnDeletion)`; never store a Codable struct containing an array as an attribute (`PROJECT_GUIDE.md` § schema).
- **Changing a synced model changes the wire:** its `syncRow()`/`apply(_:)` in `Data/Sync/`, the `va.*` migration in the FCTPlatform repo, and the contract suites (`VASyncContractTests`) move together, or none of them do.
- **Build with a CONCRETE arm64 sim destination** (`-destination 'platform=iOS Simulator,name=iPhone 17 Pro'`), never `generic/platform=iOS Simulator` — the x86_64 slice fails on cross-import overlays (`AskVillainArcAssistant.swift`).
- **Run the suite with `-parallel-testing-enabled NO`.** The per-suite simulator clones xcodebuild spawns without it die on this machine, and the death is reported as a test failure (`Channel disconnected`, `Invalid device state`, `Lost pending connection to the test runner`) rather than as the environment refusing. Serially the whole suite runs green in ~50 s; the failure signatures are in `~/Jarvis/projects/villain-arc/learnings.md`.
- **The widget extension is NOT a synchronized group** — every new file under `Data/` it compiles against (shared config types, any entity `SpotlightIndexer` references, the Diag vocabulary) must be added to its exception set in `project.pbxproj`, or the widget target silently breaks. `AppRouter.swift` compiles into the widget: main-app-only types stay out of it (the Diag vocabulary lives in the widget-safe `VADiagVocabulary.swift` for exactly this).
- **HealthKit: read `HEALTHKIT_INTEGRATION.md` first, and never "fix" the deprecated `HKWorkout` initializer by adopting `HKWorkoutBuilder.finishWorkout`** — it writes real workouts into the user's actual HealthKit store; the warning-silencing shim pattern is in `~/Jarvis/skills/apple-development/references/gotchas.md`. Health data stays device-sourced and never syncs up.
- The full trap map: `~/Jarvis/projects/villain-arc/learnings.md`.
